# Release notes style guide

Sections, in this order (omit empty ones):

1. **Breaking changes** - each with a "Migration:" line.
2. **New** - features users can try now.
3. **Improved** - faster, clearer or more reliable behavior.
4. **Fixed** - bugs users could notice.

Tone: plain, active voice, present tense, one sentence per entry, no marketing words
("revolutionary", "seamless"). Refer to issues as `#123`.

Footer: `Version X.Y.Z - released YYYY-MM-DD`.
